# Power BI DAX Reference Library

This file is an **optional extension/reference library** for the Jewelry Retail Analytics project. It is not a claim that every measure or helper table below is physically embedded in `Maryam_Jewelry_Portfolio_FINAL.pbix`.

The validated final PBIX intentionally preserves the stable working import model and primarily uses direct visual aggregations plus validated full-snapshot KPI callouts. The patterns below show how the report can be rebuilt or extended with reusable measures and an optional date dimension.

Reference aliases used below:

- Fact: `jewelry_sales` → validated transaction table (`jewelry_clean (2)` in the final working PBIX)
- Customer snapshot: `CustomerRFM` → validated RFM table (`customer_rfm (2)` in the final working PBIX)
- Optional calendar: `DimDate`

## 02 Customer & Retention

```DAX
Repeat Customers =
COUNTROWS (
    FILTER (
        VALUES ( jewelry_sales[user_id] ),
        CALCULATE ( DISTINCTCOUNT ( jewelry_sales[order_id] ) ) > 1
    )
)
```

```DAX
Repeat Customer Rate = DIVIDE ( [Repeat Customers], [Customers] )
```

The remaining customer measures use the **fixed full-history RFM snapshot** generated by Python.





## 04 Optional Time Intelligence

The validated final report uses the prepared `year_month` field directly and does **not require** a `DimDate` table. Add the following only when extending the project with reusable time-intelligence measures.

```DAX
DimDate =
ADDCOLUMNS (
    CALENDAR (
        MIN ( jewelry_sales[order_date] ),
        MAX ( jewelry_sales[order_date] )
    ),
    "Year", YEAR ( [Date] ),
    "Month Number", MONTH ( [Date] ),
    "Month", FORMAT ( [Date], "MMM" ),
    "Year Month", FORMAT ( [Date], "YYYY-MM" ),
    "Year Month Sort", YEAR ( [Date] ) * 100 + MONTH ( [Date] ),
    "Quarter", "Q" & FORMAT ( [Date], "Q" )
)
```

After creating it, mark `DimDate[Date]` as the date column, sort `Year Month` by `Year Month Sort`, and relate `DimDate[Date]` **1 → *** `jewelry_sales[order_date]`.

```DAX
Sales Previous Month =
CALCULATE ( [Gross Sales], DATEADD ( DimDate[Date], -1, MONTH ) )
```

```DAX
MoM Sales Change = [Gross Sales] - [Sales Previous Month]
```

```DAX
MoM Sales % = DIVIDE ( [MoM Sales Change], [Sales Previous Month] )
```

```DAX
Sales Previous Year =
CALCULATE ( [Gross Sales], SAMEPERIODLASTYEAR ( DimDate[Date] ) )
```

```DAX
YoY Sales Change = [Gross Sales] - [Sales Previous Year]
```

```DAX
YoY Sales % = DIVIDE ( [YoY Sales Change], [Sales Previous Year] )
```

```DAX
Rolling 3M Sales =
CALCULATE (
    [Gross Sales],
    DATESINPERIOD ( DimDate[Date], MAX ( DimDate[Date] ), -3, MONTH )
)
```

## Recommended Formatting

| Measure | Format |
|---|---|
| Gross Sales / RFM Revenue / At Risk Revenue | Currency; Millions on headline cards |
| Average Order Value / Average Item Price / Average Customer Value | Currency, 2 decimals |
| Orders / Customers / Products / Units | Whole number |
| Repeat Customer Rate | Percentage, 1 decimal |
| RFM Customer Share / RFM Revenue Share | Percentage, 1 decimal |
| Category Revenue Share / Premium Revenue Share | Percentage, 1 decimal |
| MoM Sales % / YoY Sales % | Percentage, 1 decimal |
| Missing-rate measures | Percentage, 1 decimal |

## RFM interpretation rule

`CustomerRFM` is a fixed snapshot calculated relative to **one day after the maximum observed transaction timestamp**. Do not present the segment assignments as dynamically recalculated by historical date filtering unless RFM is explicitly rebuilt as a dynamic model.
